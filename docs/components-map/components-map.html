Step details

Every process in the map, under the same headers

#Actor / StepTriggerInputContextProcessingOutput
1 Vercel Cron
Daily refresh job
Daily refresh runs
 Vercel Cron, schedule “30 0 * * *” in vercel.json (UTC). Manual “Refresh Releases” button does the same (max once per 5 min).Authorization: Bearer CRON_SECRET, checked with a constant-time compare.automation_runs row keyed release_refresh:<IST date> — a second run the same day is skipped.Computes the 7-day window in Asia/Kolkata: today − 6 … today.Starts the refresh pipeline (step 2).
2 TMDB API
Release data source
Pulls India releases
 Refresh pipeline (releases.service → TmdbReleaseAdapter)./discover/movie & /discover/tv with watch_region=IN, provider IDs 8, 119, 122/2336, release & air-date filters; a pass per users’ languages.Provider map in config/providers.ts (stable IDs first, names as fallback).Fetches details + release_dates + watch/providers for up to 160 candidates, 6 at a time, with retries on 429/5xx.Raw candidate titles with India provider listings.
3 Release Radar App
Release validator
Verifies the OTT date
 Each candidate from step 2.Release-date types per country, season air dates, original TV network, India providers.Rules in lib/release/eligibility.ts; window is never widened.Movie: India Digital (type 4) date in window → verified. Series/season premiere in window on its own platform → verified. Global digital / primary date → unverified. Old-season episodes → excluded. Duplicates collapsed.Normalised titles + release events, each marked verified or unverified_date.
4 Supabase
Catalogue store
Saves titles & releases
 Validated records from step 3.titles (unique tmdb_id + media_type), ott_releases (unique title × provider × region × event).Metadata fingerprint per title detects real changes; first_seen_at preserved.Idempotent upserts; automation_runs + integration_status updated (succeeded / partial / failed).Live catalogue + “Last synced” timestamp. On TMDB failure the last good data stays and is labelled as such.
5 Naman
Signs in & sets his taste
Sets his preferences
 Signs in (Supabase Auth, email + password) and opens My Preferences.Genres, languages, platforms, movies/series, runtime, dubbed, popular vs hidden gems, Stick / Balanced / Surprise me, mood.user_preferences row created on sign-up with the brief’s defaults.PUT /api/preferences validated with Zod; RLS + column grants let him edit only his own safe columns.Saved taste profile (Save / Cancel / Reset to defaults).
6 Naman · Vercel Cron
Discover · Friday 6 PM
Asks “what’s new?”
 Page visit, “Get AI verdicts”, “Preview My Friday Digest”, “Send Test Digest”, or cron “30 12 * * *” (= 18:00 IST) on his digest day (Friday).Signed-in session (JWT checked server-side) or CRON_SECRET.Weekly run keyed weekly_digest:<IST date> — no duplicate runs.Cron first runs a refresh, then finds users with digest on, Telegram connected and today = digest day.A request to build his personalised list (step 7).
7 Supabase
Window & profile
Loads this week for him
 Step 6.ott_releases ⋈ titles in the window, user_preferences, watchlist, viewing_feedback, ai_recommendations.Preference fingerprint (genres, languages, platforms, mode, mood…) + title metadata fingerprint.Reuses a verdict only if both fingerprints still match; otherwise the title is marked unscored.Catalogue items: verified flag, platforms, release type, watch status, cached verdict.
8 Gemini Flash
Recommendation engine
Scores each new title
 Unscored titles on his platforms + languages + content types (hard constraints first).His profile + TMDB metadata only (overview, genres, runtime, votes). Metadata is fenced as untrusted data.gemini-3.6-flash, fallback gemini-3.5-flash when busy; low thinking; batches of 12, sequential.Structured JSON → Zod schema; rejects unknown titles and verdict/score contradictions; confidence capped by metadata completeness; no synopsis invented.Verdicts saved to ai_recommendations. If Gemini fails, the catalogue still works with a retry message.
9 Release Radar App
Digest builder
Builds the Friday digest
 Scored items from step 8.Verified releases, verdicts, watchlist / “Not interested” feedback.Discovery mode: Stick = genre match only, Balanced = genre match or score ≥ 70, Surprise = any.Drops watched / not-interested, ranks by score (skips last), formats title, platform, genre, language, runtime/episodes, why, verdict, match, synopsis, TMDB link; splits under 4096 chars.Telegram-ready messages (Preview shows them without sending).
10 Telegram Bot
Delivery
Sends the digest
 Weekly cron or “Send Test Digest”.Chat ID verified via a one-time /start code (getUpdates) — never typed by the user.digest_history idempotency key weekly:<user>:<period start>; message chunks stored.sendMessage (HTML, escaped). Records each accepted chunk; classifies blocked bot, bad chat, rate limit, network errors.“sent” only when Telegram accepts every message; otherwise partial / failed with the reason.
11 Naman
Watch decision
Picks tonight’s watch
 Friday digest in Telegram or the Discover page.Watch / Maybe / Skip, match score, “Why this matches you”, filters (mood, watch time, hidden gems).Watchlist statuses: Want to watch · Watching · Watched · Not interested.Watchlist saved via /api/watchlist (RLS). “Not interested” becomes feedback that lowers future rankings.His choice for tonight; preferences never change silently.
12 Release Radar App
History & monitoring
Logs & monitors
 Every run and delivery.automation_runs, digest_history, integration_status.Live health checks (TMDB /configuration, Gemini model lookup, Telegram getMe), cached 5 min.Shows preview / test sent / weekly sent / failed, last successful delivery and next scheduled run.Errors visible in the app, details only in server logs.
Person Scheduler / trigger Release Radar app (Next.js on Vercel) Supabase (Postgres + Auth) External API (TMDB · Gemini · Telegram)
